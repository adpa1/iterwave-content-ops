# IterWave 全局运营与 UI 改造设计

> 基线：main @ 9842c12d4da4247e8a4fef80967e5e3db266e57e（2026-10-31）
> 原则：真实数据优先、账号组隔离、全局调度独立、人工确认发布、渐进迁移。

## 1. 目标与范围

本次把用户反馈的 11 项问题统一归入产品架构改造，不做彼此割裂的 CSS 补丁。分为：
- 全局运营控制：跨账号组运行矩阵、统一任务队列、调度状态、异常中心。
- 账号组业务工作台：内容生产、审核、日历、账号、配置。
- Agent 能力管理：Skills 注册、预览、启用与引用。
- 全站体验：导航、分页、加载/错误/空状态、响应式布局和数据口径。

明确不改变：账号组数据隔离；全局 FIFO 顺序；运行中的任务不因切换账号组而中断；系统不自动发布内容。

## 2. 导航与信息架构

一级导航建议：
1. 运营总览（当前账号组）
2. 全局运营中心（跨账号组，独立于当前账号组）
3. 内容工作台：热点雷达、目标策略、内容生产、内容日历、内容资产
4. 运营管理：运营控制台、数据复盘、缺口实验
5. Agent 中枢：编排与诊断、Skills、账号与登录、系统设置

快速体验不再占用侧栏一级菜单，作为运营总览首屏的主要新手入口；保留 `?page=activation` 深链接和历史链接兼容。新用户首次进入可在总览展示体验引导卡。

全局运营中心替代“全局监控 + 全局任务队列”各自为政的体验；原 URL 继续兼容并跳转/落入对应子视图。

## 3. 全局运营中心（独立于账号组）

### 3.1 页面区块
- 总览 KPI：账号组总数、可读账号组数、运行任务、排队任务、失败/中断任务、异常账号组。
- 账号组运行矩阵：账号组、数据库可用性、启用/已登录平台数、运行任务、排队数、最近活动、异常。
- 全局 FIFO 队列：队列序号、账号组、任务类型、状态、开始/结束时间、尝试次数、错误摘要。
- 定时调度：按账号组分组展示任务启用、最近执行、下次执行和错误；无数据时明确“未提供”，不猜测。
- 异常中心：任务失败/中断、数据库不可用、平台登录失效、熔断、调度器异常。
- 账号组详情抽屉/子视图：只读进入该组详情，不改变服务级活动账号组。

### 3.2 数据与隔离
- 系统级数据来自 system tenant registry 与全局 TaskQueue。
- 账号组统计通过 registry 遍历各 tenant DB，只读聚合；单组失败单独标记，不回退或混用其他组。
- 全局页面请求不得依赖当前 tenant middleware 的活动账号组上下文。
- 所有跨组 API 显式标记 global scope，并仅暴露运营者权限允许的聚合字段。
- 不把账号组数据库的业务内容写入系统库；全局汇总不复制敏感正文/凭据。

### 3.3 队列控制边界
- 保留单队列 FIFO；切换账号组不改变已提交任务的快照。
- 本轮只读观察 + 现有 queued 任务取消能力。
- 全局暂停/恢复作为后续能力：必须只阻止新入队，不杀死运行中任务；具备审计记录、确认提示和恢复机制后再开放。

## 4. 账号组创建与默认配置

- 新账号组只创建空业务空间和默认平台配置，不继承当前账号组画像。
- 不自动选择“AI 教育”或任何行业模板。
- `persona_keywords`、行业/账号定位在新建时为空；用户显式选择模板后才写入该组配置。
- 模板目录可以全局共享只读；模板的选择结果必须写入账号组自己的业务库。
- 页面分离“平台总数、启用平台数、已登录平台数、未登录平台数”，不使用无上下文数字徽标。

审查需覆盖 tenant DB 初始化、配置合并优先级、前端创建流程与行业模板 picker；禁止只隐藏 UI 默认值而保留后端自动套用。

## 5. 内容日历与计划

### 5.1 日历控件
- 月/周/日视图，上一期/下一期/今天、日期选择器。
- 可视日期范围由当前视图计算，服务端按起止日期查询；不再固定本周。
- 日期格显示计划数量和内容卡片；支持点击日期查看/创建计划。
- 草稿排期支持拖动/编辑时间；移动端采用 agenda 列表。

### 5.2 计划实体（独立于草稿）
后续增加 tenant-scoped `content_plans`：
- id、title/topic、platforms、planned_count、scheduled_at/date、status、notes、created_at、updated_at。
- 状态：planned → generating → generated → reviewed → archived/cancelled。
- 计划关联轮次/草稿采用关联表或明确外键；允许一个计划生成多个平台稿。
- 日历计划不触发发布；只有用户在内容审核/发布流程明确确认后才产生对应动作。
- 拖动排期使用乐观锁/version，防止多标签覆盖。

## 6. 内容编辑与审核工作台

采用响应式三栏结构：
- 左栏：轮次/搜索/平台/审核状态筛选、内容列表和状态。
- 中栏：标题、正文、标签、编辑历史、保存与重检。
- 右栏：平台预览、图片卡片、质量门结果、红线与审核结论。
- 桌面可折叠右栏；平板采用列表+编辑双视图；手机采用列表/编辑/预览分步。
- 保存、重新检查、驳回、删除必须明确区分；发布永远由用户确认。
- 所有栏位使用统一 Design Token，去除内联宽度导致的溢出。

## 7. Skills 注册表

当前实现是 Agent.tsx 中硬编码数组，仅作说明，不是真正注册表。改造为两层：
- 系统内置 Skill：随版本发布，元数据只读；可查看源码位置、能力说明、输入输出 schema、依赖、示例和兼容性。
- 用户 Skill：通过受控上传/创建登记，数据持久化，支持版本、启用/停用、预览、测试运行、删除/回滚。
- Skill manifest：id、name、version、description、category、inputs、outputs、permissions、entrypoint、checksum、status、created_at。
- 不允许上传文件自动执行；执行必须经过 allowlist、权限校验、沙箱/受限调用和审计。
- Agent 编排通过 skill_id/version 引用，引用缺失/禁用时阻止运行并给出诊断。
- 第一阶段仅实现“注册/预览/引用/启用状态”；不开放任意 Python/JS 代码执行。

## 8. 任务历史分页与数据准确性

当前 `/api/task-queue` 默认最多 500 条，前端把全部结果加载后渲染，既非真正分页，也会截断更早历史。改造：
- API 参数：page、page_size、status、tenant_id、task_type、from、to。
- 响应：items、total、page、page_size、pages、has_next。
- 活跃任务（queued/running）与历史任务分离：活跃区保持实时刷新；历史区服务端分页。
- 数据源以全局 TaskQueue 持久化记录为准；每个 task_id 唯一，队列状态为事实源。
- 轮次与 scheduler run 作为业务关联信息，不把同一任务在多张表的投影重复计数。
- 增加对账测试：队列任务总数、状态分布、分页全量遍历去重数一致；已取消/中断/失败记录保留。

## 9. 运行追踪与渲染稳定性

- TracePane 对所有可选字段做 schema-safe 读取；空数组、null、旧版本响应均可显示。
- 页面 API 结果通过运行时 normalize，不把 TypeScript 的静态类型当成后端数据保证。
- 页面级错误边界显示错误 ID、重试和回到总览；单区块失败不导致整页白屏。
- GlobalMonitor 当前只汇总内容/草稿/素材，不应冒充运行状态；合并后将其内容统计迁入全局运营中心的统计子区。

## 10. 全站 UI 规范

- 统一页面头部、描述、主要操作区和刷新位置。
- KPI 卡片必须填满网格列或使用合理的单列宽度；禁止单卡独占三列网格。
- 表格有空态、加载态、错误态、窄屏横向滚动和分页。
- 所有数字注明口径和更新时间；未知/未加载不显示成 0。
- 减少页面级内联样式，逐步收敛到 styles.css 的组件类。
- 统一状态标签颜色、按钮层级、间距、卡片密度、断点和焦点可访问性。

## 11. 分批实施与验收

### Phase 0：基线与设计
- 本文档作为产品/技术方案基线。
- 每批独立 PR，避免一次性大 diff。

### Phase 1：正确性与快速修复
- 明确账号组导航徽标语义，展示启用/登录的独立数量。
- 快速体验移出侧栏，保留总览首屏入口和深链接。
- TracePane null-safe，修复可复现渲染异常。
- 修复定时调度状态卡片单列占满布局。
- 最近任务先做 UI 分页；并行实现 API 真分页，不能把 500 条切片冒充完整历史。

### Phase 2：全局运营中心
- 新建独立 GlobalOperations 页面和一级导航。
- 增加全局聚合 API（账号组运行矩阵、队列、异常、定时状态）。
- 数据来源/失败边界/权限测试齐备。
- 原 GlobalMonitor / TaskQueue 深链兼容。

### Phase 3：日历与内容审核
- 日历控件月/周/日导航、可见范围 API、日期选择。
- 新增 content_plans 表和 CRUD、关联轮次/草稿、计划日历 UI。
- 审核工作台三栏重构及响应式测试。

### Phase 4：Skills 注册管理
- manifest schema、注册存储、内置/自定义来源、预览、启停、引用校验和审计。
- 仅开放安全受限的 Skill 接入，不开放任意代码执行。

### Phase 5：全站视觉验收
- 对每个一级页面执行 1440px、1024px、768px、390px 截图/布局测试。
- 检查 loading/empty/error/long content/large counts。
- 记录真机验收项，用户负责 Hark 真机最终确认。

### 关键验收
1. 新账号组行业定位为空，既不继承 AI 教育，也不继承其他账号组。
2. 4 个平台总数始终显示 4；启用/登录数准确拆分。
3. 快速体验只在首页主入口出现，旧链接仍可打开。
4. 全局运营中心切换账号组时不改变当前服务运行账号组。
5. 全局队列 FIFO 与原任务执行行为完全不变。
6. 任务历史可翻页遍历全部记录，无重复、漏项或 500 条截断。
7. 日历可切月/周/日；计划只建计划，不触发发布。
8. Skills 可注册和预览；未授权的代码永不执行。
9. Trace/运行状态面对空值和旧响应不白屏。
10. 所有页面的数字有真实来源、时间和明确口径。
