# 账号组即时热切换验收清单

## 安全开关

即时热切换默认关闭。只有在测试/预发布环境完成下列验收后，才显式设置：

```bash
ITERWAVE_ENABLE_TENANT_HOT_SWITCH=true
```

未设置或设为其他值时，账号组选择保持旧行为：仅保存选择，重启后生效。生产环境在人工验收通过前不要启用该开关。

## 自动化覆盖

- HOT-001～004：运行时构建器为不同账号组创建独立 SQLite 文件、账号 key 命名空间、读写隔离和调度器数据库绑定。
- HOT-005～007：A→B→A 切换、目标调度器启动失败回滚、目标初始化失败时旧运行时不变。
- HOT-008～010：在途请求排空、排空超时恢复、并发切换互斥。
- HOT-011～012：调度器等待在途任务，超时则恢复旧调度器。
- HOT-013：终止旧账号组扫码登录子进程，等待登录态导出线程，并保留已导出的 storage_state。
- HOT-014：切换时清除进程级热点采集/研判状态；任务仍运行时拒绝清理。
- HOT-015：回滚失败时请求闸门保持关闭；默认配置不启用即时切换。

## 真机 / 真实服务验收

测试前准备两个账号组 A、B，各自使用不同的业务内容、平台登录态和素材。不要使用自动发布；平台发布按钮仍必须由人工操作。

1. **A→B→A 循环**：在 A 创建一条测试内容和一份素材，切换到 B 后确认二者不可见；在 B 创建不同内容，再切回 A，确认 A 的内容和素材完整保留。重复至少 5 轮。
2. **登录态隔离**：在 A 启动扫码登录后发起切换。切换应等待或终止旧扫码进程，不能让 A 的二维码、Cookie 或 storage_state 写入 B 目录。回到 A 后验证原有登录态仍可用。
3. **轮次与后台任务**：有轮次运行时尝试切换，应等待安全结束；热点采集/研判正在执行时应等待完成，不能在任务仍访问 A 数据时切到 B。
4. **请求排空**：切换期间发起状态查询、素材下载和其他 API 请求。新业务请求应收到可重试的 503；已开始的请求应完成后再提交切换。
5. **失败回滚**：在测试环境临时让目标账号组数据库初始化或调度器启动失败。界面应显示明确错误，运行账号组保持 A，A 的调度和数据访问恢复。
6. **回滚失败保护**：仅在隔离测试环境模拟旧账号组恢复失败。新业务请求必须保持被阻断，不能自动回退到任意账号组；随后通过重启恢复服务。
7. **界面状态**：切换过程中显示“切换中…”，成功后工作台刷新且显示 B 的数据；失败后保留原账号组并展示错误原因。
8. **日志核对**：检查服务日志没有跨账号组数据库路径、账号标识、登录态目录串用。确认完成后再决定是否在目标部署环境启用开关。

## 上线门槛

- CI 的后端测试、Python 编译/安全边界检查和前端构建全部通过。
- 上述真实环境验收通过并记录结果。
- 没有验证前保持 `ITERWAVE_ENABLE_TENANT_HOT_SWITCH` 关闭。
