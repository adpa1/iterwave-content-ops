# IterWave P0-P2 阶段交付记录

## P0：快速体验到正式生产交接

- 已保存样稿可一键创建正式生产轮次并导入。
- 导入时重新执行正式质量门；检查失败或异常时拒绝导入。
- 导入后写入正式 `contents` 与 `drafts(draft_pending)` 记录。
- 样稿与正式内容建立持久化关联，重复点击幂等。
- 正式轮次状态必须为 `created`；已开始执行的轮次不允许追加。
- 不自动生成图片、不自动存平台草稿、不自动发布。
- AI 内容声明由发布平台负责；IterWave 不保存 AI 生成属性或平台声明元数据。

## P1：业务时区与激活指标

- 新增 IANA 业务时区配置，默认 `Asia/Shanghai`。
- 系统设置支持修改时区；无效时区被拒绝。
- API、轮次执行、断点恢复、自动闭环、运营引擎、熔断器、目标进度、分析、计划版本、通知、评分时间窗口和 APScheduler 统一使用业务时区。
- APScheduler CronTrigger 明确使用业务时区；时区变更保存后提示重启，以确保已注册任务和日期触发器全部切换。
- 激活指标增加当前数据库内可观测 Cohort 的 TTV P50/P90、样本数及范围说明。
- 跨独立安装实例的总体 TTV 分位数尚需用户授权的匿名遥测汇总服务，不能用单机样本冒充总体统计。

## P2：托管模型服务

- 已完成托管模型网关、成本/配额、安全、隐私、滥用控制、可靠性和跨安装实例遥测的实施方案与验收门槛。
- 未启用平台代付模型服务；BYOK 继续作为唯一可用模式。
- 原因：上线前仍需明确运营主体、成本预算、供应商/地区、数据处理条款和遥测授权。
- P2 到此停止，等待产品负责人决策，不继续开发 Hosted 付费链路。

## 真机验收

- 体验样稿导入正式轮次、编辑、质量复核、生成图片、存平台草稿等流程需要在用户环境真机验收。
- 时区切换需重启服务后验收每日配额重置、运营窗口和 Cron 定时任务。
- 本地/CI 测试通过不等于真实平台浏览器流程通过。
