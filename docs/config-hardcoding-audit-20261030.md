## 一、结论

本轮专项审查发现的运行策略硬编码、配置元数据缺口、前端编辑缺口和内部信息泄露，均已完成对应改造。

**当前配置体系的事实来源：**
1. `config/config.yaml`：部署初始值。
2. Pydantic `Config`：类型、范围和跨字段关系校验。
3. 账号组 SQLite `tenant_settings`：运行时配置覆盖的唯一持久化事实来源。
4. `patch_config()`：校验后写入 SQLite、更新当前内存配置并记录版本与审计。
5. 启动/账号组热切换：从 SQLite 读取并套用运行时覆盖。

旧 `config_overrides.json` 只保留迁移/恢复兼容读取和显式恢复工具，不属于正常配置更新链路。没有把所有数字都搬进数据库；安全上限、协议常量、数学定义和纯展示常量继续保留在代码中。

## 三、配置元数据和前端编辑器补齐

此前存在“后端可以修改，但元数据没有描述”以及“元数据存在，但编辑器没有入口”的问题。本轮已补齐：

- 评分活跃维度门槛、收缩参数、时效半衰期。
- 节奏间隔字段。
- 热点去重相似度和长度预筛参数。
- 平台启用状态。
- 选题库类型、字段映射及远程请求超时。
- 全局目标、平台画像、平台协同字段。
- 通知事件启停。
- 自动闭环、文案生产、平台分析、目标规划、螺旋复盘、调度宽限期、登录与恢复超时等策略分组。

`RuntimePolicyEditor` 已支持布尔复选框，并按元数据类型提交布尔值，不再把布尔值当字符串提交。复杂配置仍由专用编辑器管理。

新增回归测试要求：**所有 `SCALAR_RULES` 白名单字段都必须出现在配置元数据中**，防止后端新增字段后再次漏掉配置中心入口。

## 四、无效配置与重复定义治理

- 删除未被运行逻辑读取的 `CircuitBreakerConfig.signals` 和 `recovery` 字段。熔断恢复的冷却、登录验证、轻量动作验证仍是不可关闭的安全流程。
- 删除未使用的热点刷新间隔字段，刷新调度由 scheduler job 配置负责。
- 普通 `patch_config()` 不再写旧 JSON 文件。旧 `_save_overrides()` 仅保留为显式迁移/恢复兼容工具和测试工具，不在正常运行时配置更新链路中调用。
- 配置字段增加类型、范围和跨字段校验，包括热点趋势阈值、文案长度/标签范围、螺旋复盘建议数量范围。
- 统一热点采集来源的默认定义：默认公网来源只存在于 YAML 配置中；显式清空来源后不再静默回退到代码中的硬编码公网源。
- 采集重试从字符串解析改为结构化数值，消除解析失败后隐式回退默认值的问题。

## 五、内部信息泄露修复

此前只隐藏了部分配置元数据，实际配置视图和个别诊断响应仍会泄露内部字段。本轮已修复：

- `current_config_view()` 不再向前端返回平台 `account_key` 和适配器 `base_url`；平台设置页删除对应编辑框。
- 普通配置 PATCH 拒绝修改平台内部标识、平台适配器地址、图片/视觉服务端点和 Webhook 环境变量名。
- 配置历史与覆盖视图对平台端点和内部账号标识脱敏。
- Webhook 环境变量名、LLM API Key 写入接口的环境文件路径不再出现在 API 响应中；通知页面只显示是否配置。
- 图片生成缺少密钥时使用通用错误文案，不再回显环境变量名。
- LLM 连通性诊断不再显示 `llm.api_key_env`。

这些字段仍可存在于服务端部署配置中，但不会通过普通配置中心接口下发或修改。

## 六、明确保留在代码中的常量

以下不是应该放入账号组运行配置的业务参数：

- **安全和资源硬上限**：网络响应体大小、重定向次数、上传/解压大小、图片最大尺寸/像素/响应体、备份容量、登录数据目录权限、租户 ID 格式、认证与会话限制。配置值只能收紧，不能突破代码硬上限。
- **不可关闭的安全流程**：发布人工确认、可发布性检查、账号组隔离、熔断三步恢复、失败关闭行为。
- **平台协议和数据结构**：平台状态/事件枚举、数据库结构、JSON 协议、HTTP 状态码、文件格式标识、哈希与 ID 生成规则、迁移版本号。
- **数学定义**：百分位计算、相似度算法、评分公式、归一化公式、指数衰减公式。业务参数可以配置，公式本身应随代码版本管理。
- **纯展示细节**：卡片像素坐标、颜色、字体尺寸、间距、渐变和折行规则。
- **提示词版本与平台适配协议**：作为代码版本化内容发布，避免管理员配置破坏协议和安全要求。
